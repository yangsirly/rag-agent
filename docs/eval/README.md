# RAG 评测集

> 状态：v1 骨架（2026-07-26，批次 5 产出，见 [agent-test-plan.md](../plans/agent-test-plan.md) 第 6 节）
> **本目录当前只定格式**：两个 JSONL 里的题目是格式示例（业务内容为虚构的差旅报销知识库），
> 必须在知识库里程碑用真实语料替换后才能产出有意义的分数。

## 1. 目录

| 文件 | 用途 |
| --- | --- |
| `retrieval-golden.jsonl` | 检索评测集：query → 应命中哪些文档。字段定义见计划 6.1 节 |
| `answer-golden.jsonl` | 答案评测集：问题 → 必含事实点 / 必引文档 / 是否应拒答。字段定义见计划 6.2 节 |
| `metrics.md` | 每个指标的计算口径，**先读它再跑分** |
| `baselines/` | 每次跑分的报告存档 |

两个 JSONL 的格式由 `src/test/java/yangsirly/rag_agent/agent/EvalDatasetFormatTests.java`
在 `mvn test` 中校验（每行合法 JSON、字段齐全、`relevantChunkIds` 留空、至少一道应拒答题）。
**格式进 CI，评测本身不进**。

## 2. 什么时候跑、怎么跑

- **eval 不进 `mvn test`**：评测调用真实模型与检索，慢且有成本，走独立脚本或独立 profile，
  在 RAG 里程碑后手动或定时执行；
- 每题跑 **3~5 次**，记均值和方差——模型输出有随机性，只看单次结果会被骗；
- 每次跑分产出一份 `baselines/YYYY-MM-DD-<变更简述>.md`，记录**改了什么 → 分数怎么变**。

### 基线报告模板

```markdown
# 2026-08-15-切换分块策略为按标题分段

## 本次变更
（一句话：改了什么、为什么）

## 分数对比
| 指标 | 上次基线 | 本次 | 变化 |
| --- | --- | --- | --- |
| Recall@5 | 0.82 | 0.86 | +4.9% |
| ...      |      |      |      |

## 方差异常的题
（方差 > 均值 20% 的题号及现象）

## 结论
（是否作为新基线；若回退，回退到哪份）
```

## 3. 门禁口径

**相对上次基线不下降超过 5%**，不是绝对分数（见 `metrics.md` 第 5 节）。
唯一例外是越权泄露率：**恒为 0**，绝对门禁，任何非零值立即阻塞。

## 4. 数据约定与待回填项

- `relevantChunkIds` 现在一律为空数组——**这是刻意的**：query 和"应命中哪篇文档"现在就能标，
  chunk 粒度要等分块策略定型（协议待定项 T-6）后回填；
- docId 使用可读占位形式 `kb-1/doc-3`（协议 4.4 节）：评测题目在真实语料导入前没有数据库 ID，
  导入时必须回填为真实的 `{knowledgeBaseId}/{documentId}`（如 `1/50`）；
- `mustInclude` 写**事实点**（如 `"30 天"`），不写整句参考答案——否则模型换个说法就误判失败；
- `shouldRefuse:true` 的题必须保持一定占比：知识库里没有的问题，模型编答案是 RAG 里
  最危险的失败模式；
- 题目 `tags` 用于分层看分：`单跳` / `多跳` / `否定型` / `无答案` / `事实型`。
